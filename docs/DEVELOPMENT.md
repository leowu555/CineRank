# Local development

This is the repeatable startup path for CineRank. Secrets and env vars: [`CONFIGURATION.md`](CONFIGURATION.md).

## Supported runtimes

| Tool | Claim | Verified here |
|------|--------|----------------|
| Python | Django 6.0 supports 3.12–3.14 | **3.13.12** used to compile the lock and to install/test it. **3.12 was not installed or tested.** |
| Node.js | Vite 8.0.7 requires `^20.19.0 \|\| >=22.12.0` | **v24.14.0** (`npm ci` + production build) |
| npm | lockfileVersion 3 | **11.9.0** |
| PostgreSQL | 16 | Homebrew `postgresql@16` on macOS (startup path; not re-tested in 1.2) |

`python3` on macOS is often Apple’s 3.9, which **cannot** run this project.

Do not treat “Django supports 3.12” as “this lock was proven on 3.12.”

The AWS Lambda movie API zip was built from macOS wheels. That is **not** a validated Linux/Lambda image.

## Backend dependencies

- **Direct:** `backend/requirements.in` (packages the app imports or needs at runtime).
- **Lock:** `backend/requirements.txt`, generated by pip-tools `pip-compile` in a throwaway venv. Do not hand-edit it.
- **Compiler:** `backend/compile-requirements.sh` uses Python 3.12+ and **pip-tools==7.6.1**. Override the interpreter with `PYTHON=/path/to/python ./compile-requirements.sh`.

`djangorestframework-simplejwt` is **not** in the lock. Auth remains DRF **TokenAuthentication**. `narwhals` is a **scikit-learn 1.9** transitive dependency.

### Install vs leftover packages

`pip install -r requirements.txt` **installs or upgrades** packages named in the lock. It does **not** uninstall packages that are missing from the file (for example leftover `djangorestframework-simplejwt` in an old venv).

| Goal | What to do |
|------|------------|
| Reproducible setup | Create a **new** virtualenv directory, then `pip install -r requirements.txt`. |
| Existing venv | You may `pip install -r requirements.txt` to get locked versions of listed packages; extras can remain. |
| Make an env match the lock exactly | `pip-sync requirements.txt` (pip-tools) in **that** env. Do not run this against a venv you did not create for that purpose. |

Never run `python3.X -m venv venv` on top of an existing `backend/venv` to “switch Python.” Create a **separate** directory (for example `venv-3.13`) and point your activate path at it.

### Platform note

`psycopg2-binary` and NumPy/SciPy wheels are OS- and architecture-specific. Recompile or install on the target OS when packaging for AWS.

Lambda package (same workflow as before):

```bash
cd backend
pip install -r requirements.txt -t build/lambda
cp -R config movies accounts ratings recommendations watchlist manage.py build/lambda/
cd build/lambda && zip -r ../lambda.zip .
```

Handler: `config.lambda_handler.handler`.

## Frontend dependencies

Keep **npm**. Manifest: `frontend/package.json`. Lock: `frontend/package-lock.json`.

```bash
cd frontend
npm ci
```

`npm install` may rewrite the lockfile. Do not upgrade packages unless a later task requires it.

`npm audit` findings are **not** the same as a confirmed exploit in this app. See [`ROADMAP.md`](ROADMAP.md) task **1.6**. Do not run `npm audit fix --force`.

## First-time / clean machine startup

Database creation, migrations, and demo seeding are **explicit**. Ordinary `runserver` does not reset data or create demo users.

### 1. PostgreSQL

```bash
brew services start postgresql@16
createdb movie_recommender   # first time only; skip if the database exists
```

### 2. Backend environment (fresh directory)

```bash
cd backend
python3.13 -m venv venv          # only if venv/ does not already exist
source venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If `venv/` already exists, activate it; do not recreate it in place. To use a different Python, pick a new folder:

```bash
python3.13 -m venv venv-3.13
source venv-3.13/bin/activate
pip install -r requirements.txt
```

### 3. Environment file

If `backend/.env` **does not** exist:

```bash
cp .env.example .env
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Paste the key into `SECRET_KEY`. Set `TMDB_API_KEY` and `DB_*`.

If `.env` **already** exists, do not overwrite it. Add any missing keys from `.env.example`.

### 4. Migrations (explicit)

```bash
python manage.py migrate
```

Optional demo accounts (`alice` / `bob` / `carol`, password `demo1234`) — only when you want seed data:

```bash
python manage.py shell -c "exec(open('seed_demo_data.py').read())"
```

### 5. Run API and UI (two terminals)

Terminal A:

```bash
cd backend
source venv/bin/activate
python manage.py runserver
```

Terminal B:

```bash
cd frontend
npm ci          # first time or after lockfile change
npm run dev
```

API: `http://127.0.0.1:8000` · UI: `http://localhost:5173`

### 6. Established checks

From `backend/` with `SECRET_KEY` set (`.env` or the environment):

```bash
DJANGO_SETTINGS_MODULE=config.test_settings python manage.py test
python manage.py check
python -m recommendations.recsys.cli --skip-download
```

`config.test_settings` uses in-memory SQLite (no Postgres). Optional isolated Postgres (creates/drops `cinerank_isolated_test`, not `movie_recommender`):

```bash
DJANGO_SETTINGS_MODULE=config.test_settings_postgres python manage.py test
```

Frontend production build (optional):

```bash
cd frontend
npm ci
npm run build
```

Do not call live TMDB or deploy Lambda as part of ordinary startup.
